## 前提ゲート

## 最小計測の候補

| 計測対象 | 目的 | 備考 |
| --- | --- | --- |
| 主要CTA総数 | CTA総量の把握 | `click_consultation_cta` など仮名。正式名は実装時決定 |
| CTA位置別 | どこで押されるか | hero / middle / final 等 |
| 主要セクション到達 | どこまで読まれているか | 訴求ブロック別 |
| LINE導線 | 副CV反応の把握 | 初回で入れる場合のみ |
| 資料DL導線 | 将来導入時 | 初回制作に含めるなら |
| フォーム開始 / 送信 | 送信着手と送信完了の区別 | native form を壊さない |
| UTM保持 | 流入別比較の下地 | hidden 項目や cookie 方針要確認 |

## この案件で特に注意すること
- 予約導線が手動のままだと `予約完了` が計測できない可能性が高い
- LINE 経由相談は証跡が弱くなりやすい
- LPイベントだけで `契約率改善` を断定しない
- 送信着手と送信完了を混同しない
