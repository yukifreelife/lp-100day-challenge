## 何を判断したか
- day048 は新規初期化ではなく、day047 の整理結果をそのまま引き継ぐ継続 day とする。
- 最初の確認事項は `CLIENT_REPLY_006_PREP_SCOPE_AND_WP_CHECK.md` の送信有無で固定する。
- クライアントは価格の多寡だけでなく、`その金額で何がどこまで含まれるか` を判断材料として見ている。
- 次返信では、`含む / 含まない / 前提条件 / 修正の考え方 / 変動要素` を一体で示す必要がある。
- その次の段階では、`見積りを一式で見せるか / 工程内訳を見せるか` と `無理のない受注条件` が判断材料になる。
- ここまで来たら、次は `概算見積り` と明示して具体額を置いた方が会話が前に進みやすい。
- 金額幅が広いと再び抽象往復になりやすいので、加算条件は固定額へ寄せた方が判断しやすい。
- 正式見積り直前では、金額より `運用基準の明確さ` を優先して答えた方が前に進みやすい。
- さらに一段進むと、クライアントが知りたいのは `次に何を送ればよく、送った後にどこまで見てもらえるか` になる。
- 実際に材料が届いた段階では、抽象的な見積り説明より `この内容なら概算内で進めやすい` と `追加確認点はここ` を明示する方が前に進みやすい。

## 詰まり
- WordPress 環境制約は引き続き未確認なので、反映可否は条件付きのまま扱う必要がある。
- 公開後軽微修正の範囲や修正回数は、見積前提として置けるが、まだ正式合意ではない。
- 想定金額帯は返せるが、WordPress 制約未確認のため正式見積りとしての確定はまだできない。
- 具体額を出す場合も、WordPress 環境確認前なので `正式確定ではない` 線引きが必要。
- 固定額化しても、WordPress 制約の強さによっては本来工数差が出るため、正式見積り前の確認事項は外せない。
- クライアントが本当に知りたいのは `追加条件の言葉` ではなく、`自分のケースがどちらに当たるか` だと分かった。
- 正式見積り前でも、一次レビューとして `進められる / 追加確認が必要` の見立てを返すと、材料提出のハードルが下がる。
- WordPress 前提が SWELL / ブロックエディタ / Contact Form 7 と分かったことで、追加対応の有無は `テーマ制約の強さ` と `フォーム項目変更の要否` にほぼ集約できる。

## 学び
- restart brief が先にあると、翌 day の入口整備は `何を複製し、何を更新するか` を迷わず決めやすい。
- 継続案件はテンプレ再初期化より、直前状態を丸ごと持ち上げた方が整合を崩しにくい。
- 受注判断段階では、価格表そのものより `条件が揃ったときの進めやすい範囲` を言語化した方が納得感が高い。
- クライアントの不安が `安さ` ではなく `認識ズレ` にある場合、受ける側の判断基準を率直に出した方が信頼につながる。
- 堂々巡りになり始めたら、`幅のある説明` から `ベース金額 + 加算条件` に切り替えた方が進めやすい。
- クラウドソーシング相場を参考にするなら、細かな金額幅より `+5,000円` `+10,000円` `+20,000円` の固定額の方が伝わりやすい。
- さらにその先では、4つの具体論点に一問一答で返した方が、正式見積り前の判断が進みやすい。
- 今回の段階では、詳細説明より `その進め方で問題ない` と `この材料で一度判断できる` を明言する方が重要だった。
