## 2. 良かった点

### 1. スコープ管理が前回より明確に改善したこと
受注前から`含む/含まない`をESTIMATE_SCOPE_MATRIX.mdで整理し、WordPress反映、公開後レビュー、計測整備を別フェーズとして明確に分けた点は評価できる。
前回のような「やりながら範囲が膨らむ」事故は回避できており、実務的なスコープ感覚が身についてきている。

### 2. WordPressテーマとして再利用可能な納品物を作れたこと
静的LPからWordPress自作テーマへの移行は、functions.php（OGP/CF7連携）、style.css、index.phpを適切に分離しており、技術的には実務レベルに達している。
Contact Form 7との連携、OGP設定、レスポンシブ対応まで含んでおり、単にHTMLをWordPressに載せただけではない。

### 3. 納品後のトラブル対応が実務的だったこと
CF7のID特定、PCフォームのレイアウト修正、外部画像の表示崩れ、ファイルサイズ超過（34MB→4MB）など、実務で頻出する問題に順番に対処できた。
特にファイルサイズ最適化（88%削減）は、WordPressのアップロード上限問題を知っているからこその適切な対応。

### 4. インストール手順書・ロールバック手順書まで整備したこと
INSTALLATION_GUIDE.md、BACKUP_ROLLBACK_GUIDE.md、CONTACT_FORM_7_SETUP_GUIDE.mdなど、納品物の周辺ドキュメントが整っている。
実務では「作って終わり」になりがちだが、運用・保守の視点が含まれている点は評価できる。

### 5. クライアントとのやり取り記録が体系的になったこと
CLIENT_MESSAGE_INDEX.mdで37件のメッセージ往復を追跡可能にし、HANDOFF_LOG.mdで判断の理由と次アクションを時系列で残している。
長期案件や複数人関与案件で威力を発揮する仕組み。

### 6. 実装方式（SWELL vs 自作テーマ）を比較提案できたこと
単に「作ります」ではなく、SWELL利用と自作テーマ開発のメリット・デメリットを提示し、クライアントに選択肢を提供した点は良い。
「将来的な柔軟性と独自性」を理由に自作テーマを選択してもらう流れは、説得力がある。

## 3. 厳しく見ると弱い点

### LP品質
**何が弱いか**
LPは全体として丁寧で無難だが、強い差別化や「今ここで相談したい」と思わせる引力は弱い。

**なぜ弱いか**
訴求が「何から見直せばいいか分からないとき」という問題提起は正しいが、競合が多い製造業採用支援市場で「なぜこの人なのか」の独自性が薄い。
事例も「見学問い合わせが出るようになった」「発信内容に一貫性が出た」といったプロセス記述で終わっており、「採用できた」「定着した」という成果まで届いていない。

**実案件でどう不利になるか**
広告流入や比較検討で勝ち切るには弱い。`悪くない`で止まると、問い合わせ率は伸びにくい。

### 提案の質
**何が弱いか**
制作技術は向上したが、クライアントの事業成果に深く踏み込む提案はまだ弱い。

**なぜ弱いか**
今回の提案は、コピー調整、レイアウト、実装方式、画像差し替えが中心。
「見学後の歩留まり」「求人経路別の質の差」「相談後の成約率」など、採用成果に直結する論点にはまだ踏み込めていない。

**実案件でどう不利になるか**
制作はできるが、「事業を前に進めるパートナー」という評価にはまだ届かない。

### クライアント理解
**何が弱いか**
製造業向けの悩み理解は前回より良いが、`採用事業そのもの`の深掘りは浅い。

**なぜ弱いか**
応募不足、見学導線、発信テーマ整理までは見えているが、実際の受注構造、対応工数、見学後のクロージングプロセスなど、商売の内側までは十分に分解していない。

**実案件でどう不利になるか**
LPで解決できる問題と、商品設計や営業設計側の問題を切り分けられないと、改善が浅くなる。

### CRO / 計測視点
**何が弱いか**
納品完了までの再現度は高いが、改善運用の入口としては弱い。

**なぜ弱いか**
SKILL_PROGRESS_CHECKLIST.mdでも、GA4/GTM/Looker周辺は`クライアント側`または`未実施`になっている。
つまり、`公開して終わらない設計`まではまだ組めていない。

**実案件でどう不利になるか**
初回納品はできても、継続改善や上流提案で単価を上げにくい。

### プレビュー確認方式
**何が弱いか**
Localや`.local`をこちらから直接見られず、クライアント確認前提で話を進めた箇所があった。

**なぜ弱いか**
実務では頻出する問題だが、標準ルートとしては弱い。外部共有可能な確認URLを最初から持つべき。

**実案件でどう不利になるか**
「開発者側で正常に見えているが、クライアント環境で崩れている」という認識ズレのリスクがある。

### 継続受注へのつながり
**何が弱いか**
前回同様、継続提案の武器はまだ弱い。

**なぜ弱いか**
今回も案件は単発で閉じられており、`次に何をどの順で提案するか`が商品としてはまだ弱い。
計測整備やCROは「継続契約時に提案」としているが、具体的なプラン形にはなっていない。

**実案件でどう不利になるか**
初回案件が終わった後、次の売上につながりにくい。

## 4. 見落とし・甘さ・詰め不足

### 1. 画像運用方針を初期に固定できていない
今回もっとも分かりやすい甘さはここ。
外部画像を使っていたため、本番確認段階で表示崩れが出て、さらにローカル化、さらに画像提供、さらに圧縮と、終盤の手戻りが連鎖した。
着手時に`クライアント素材 / フリー素材 / ローカル格納 / ライセンス管理`を固定すべきだった。

### 2. ファイルサイズ上限の事前確認が不足していた
WordPressのアップロード上限（通常2-10MB）に対し、初版テーマが34MBだったことは、事前確認不足。
「高解像度画像をそのまま使うとファイルサイズが膨らむ」ことは経験則で予測できるはず。

### 3. クライアント向け説明と内部実装のズレを生みやすい
仮案件運用上の都合で、クライアントには2枚だけ送った前提で話しつつ、実装側では他画像も差し替えている。
今回は仮案件だから回せたが、実案件なら相当に危ない。

### 4. 100,000円の中に載せた内容がまだ重い
今回の中身は、受注前整理、コピー往復、静的LP、WordPressテーマ化、CF7連携、画像ローカル化、ファイルサイズ最適化、手順書まで含まれている。
これはかなり重く、前回よりもさらに`安く受けすぎ`の傾向がある。

### 5. 編集しやすさの約束は限定的
今回の自作テーマは、文言・リンク・画像差し替えの一部は管理画面からできる想定だが、レイアウトやデザイン調整は結局相談前提。
営業時の説明を少しでも誤ると、相手は`自由に触れる`と誤解しやすい。

### 6. 品質確認の証跡が弱い
実際に確認はしているが、Lighthouse、CLS、レスポンシブ、フォーム確認などの証跡を標準化できていない。
完了の説得力は、まだ口頭・文面寄り。

### 7. 改善運用の地図がまだ薄い
Must 8/14、クライアント側込み11/14という整理は良い。
ただ、それを`次回どう売るか / 何を切り出すか`まではまだ弱い。

## 9. この案件で最も痛い3つの課題

### 1位: 改善運用まで初回提案に載せ切れていない
#### なぜ重要か
納品完了までは強いのに、その後の売上につながる継続提案が弱い。
ここが弱いと、案件が単発で終わりやすい。

#### 今後どう直すべきか
初回提案の時点で、
- `制作のみ`
- `制作 + 初回レビュー`
- `制作 + 1か月改善伴走`
を分けて見せるべき。

### 2位: 画像 / プレビュー / 容量の運用方針が初期に固まっていない
#### なぜ重要か
今回の大きな手戻りの多くはここから来ている。
終盤の連鎖修正は、利益を削りやすい。

#### 今後どう直すべきか
着手時に、
- 素材の出どころ
- 外部依存の可否
- 保存方式
- 共有URL
- 想定アップロード容量
を必須確認に入れるべき。

### 3位: LPの刺さりやすさがまだ「無難」の域を出ない
#### なぜ重要か
技術力が上がっても、LPの説得力が弱いと「制作屋さん」で止まる。
単価を上げるには、訴求力も同時に上げる必要がある。

#### 今後どう直すべきか
- 事例をプロセス記述で終わらせず、成果（採用数、定着率）まで掘る
- 「なぜ他社ではなくこの人なのか」の独自性を強化する
- 競合比較に耐えられる差別化ポイントを明確にする

## 10. 経営者目線での結論

- このやり方は**前回よりマシで、部分的には実務投入できる**。
- ただし、**そのまま量産するとまだ消耗しやすい**。

### 標準化すべきもの
- 受注前整理票
- スコープ / 金額分離テンプレ
- 素材 / 画像 / プレビュー確認テンプレ
- 納品手順書
- クローズログ
- ファイルサイズ上限チェックリスト

### 都度判断にすべきもの
- SWELLか自作テーマか
- 画像ソース選定
- 初回から計測を含めるか
- 継続提案をどの深さで出すか

### 総合判定
**前回案件より着実に進歩しており、70点は妥当。**
前回が`形は整っているが、成果責任と実務の詰めが甘い`なら、今回は
**`実務の流れはかなり整ったが、改善責任と標準化の詰めがまだ甘い`**という評価。

次回の案件で、
- 計測・改善の初回提案
- 画像 / preview / upload方針の先出し
- LPの刺さりやすさ向上

まで改善できれば、`75点台後半〜80点前半`に乗せられる可能性は十分ある。

## 12. 次回案件で点数を10点以上上げるための最短アクションプラン

**「流入 → LP → 相談 → 見学 → 採用」**の全体ボトルネックを1枚で整理する。

**「制作のみ / 制作+計測 / 制作+改善伴走」**

LPの刺さりやすさを、
**競合2社との比較表**
を作るレベルまで上げる。
