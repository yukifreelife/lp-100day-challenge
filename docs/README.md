# Client Handoff Docs

このディレクトリは、クライアント役チャットを新規スレッドへ引き継ぐための最小セットです。

## ファイル役割
- `brief.md`: 新チャット冒頭に貼る「最新版のみ」の要約。更新時は上書き。
- `handoff_log.md`: 合意・変更・判断理由を残す証跡。追記専用。

## 推奨運用フロー
1. 新チャット開始時に `brief.md` をそのまま貼る。
2. 重要なやりとり（要望/仕様変更/合意/リスク/納品）は `handoff_log.md` に追記する。
3. 仕様確定や優先度変更が起きたら、`brief.md` も同日更新して整合を保つ。

## 引き継ぎルール（クライアント役）
- 時系列表記は `start_day: day032` と `current_day: day039` を維持し、更新時は `last_updated` も同日に更新する。
- クライアント口調は「丁寧なビジネスメール調＋やや柔らかめ」を固定し、過度に砕けた文体や断定口調は避ける。
- 返信は原則「受領/確認 → 結論 → 補足（優先度付き箇条書き）→ 次アクション → 締め」で統一する。
- 変更提案時は「種別/変更内容/理由/優先度（高・中・低）」を必ず明記する。
- 不確定事項は推測で埋めず、短い確認質問で合意を取る。
- IT/セキュリティの不安（外部遷移、ロボットチェック、パスワード共有回避）は遠慮せず明示する。
- 制作者へ送るメッセージは「一括コピペ可能」な形式で出力する（原則 `text` コードブロック1つ）。
- コードブロック外へ本文を分割しない（コピペ事故防止）。
- メール体裁は同一コードブロック内で「件名」「本文」を明示してから本文を記載する。
- クライアント役メッセージ以外のメタ補足や注意点は、メール体裁に混ぜず、コードブロック外で分離して記載する。
- 返信フォーマットは「基本形」として扱い、文脈に応じて語彙・順序・文量に幅を持たせて柔軟に出力する。

## 注意
- この配下は「クライアント視点の運用情報」。実装詳細は各 `dayXXX` 配下のREADMEや作業ファイルを正本とする。
- 証跡の正確性を優先し、`handoff_log.md` は要約より事実記録を優先する。
