## Findings

### [高] 特商法表記のEC必須項目が不足している

- 根拠: `src/data/siteData.js` の `legal.businessRows` は「販売事業者」「所在地」「問い合わせ」「販売価格」「商品代金以外」「返品」の6項目のみ。
- 不足: 代表責任者、電話番号または代替連絡手段の具体性、メールアドレス、支払い方法、商品の引き渡し時期、申込有効期限、販売数量などが表示されていない。
- 影響: 架空通販デモとしても、購入判断に必要な取引条件の表示例として不完全に見える。
- 補足: 生成モックには「お支払い方法」「引き渡し時期」「お問い合わせ」などの枠があるが、実装では省略されている。

### [高] 問い合わせ窓口が抽象的で、実際に到達できる導線が確認できない

- 根拠: 特商法表記は「サイト内フォームより受付」、プライバシーポリシーも「サイト内フォームよりお問い合わせください」と表示している。
- 問題: day099内で法務ページから問い合わせフォーム、メール、電話番号、受付時間へ到達できる証拠がない。
- 影響: 特商法表記と個人情報窓口の両方で、連絡先の具体性が不足している。

### [中] 返品条件がページ間で矛盾している

- 根拠: 法務データは「未使用品に限り到着後7日以内に受付」。カートの信頼要素は「30日間返品保証」。
- 影響: 購入直前の表示と法務表示が食い違い、販売条件の明確性を損なう。
- 評価: 法務観点では、返品・キャンセル条件は全ページで同一条件に揃える必要がある。

### [中] 法務ページ内アンカーが実ブラウザで機能していない

- 根拠: `ORCHESTRATOR_LEGAL_ANCHOR_TEST.md` では `#legal` から「プライバシーポリシー」をクリック後、DOMがHomeページになっている。
- 実装根拠: `src/pages/Legal.jsx` 内のタブ風リンクと法務ページ内フッターが `#commerce` / `#privacy` を使っている。
- 影響: プライバシーポリシーへ移動できないため、法務情報へのアクセス性が低い。

### [中] プライバシーポリシーの更新日と運営主体の特定情報が不足している

- 根拠: `src/pages/Legal.jsx` のプライバシーポリシーには「最終更新日」の表示がない。
- 不足: 運営主体、個人情報管理者または窓口、具体的な問い合わせ先、Cookie/アクセス解析、ポリシー変更時の扱いが薄い。
- 影響: 個人情報の取扱いページとして、いつの内容で誰が責任主体かが分かりにくい。

### [低] 「所在地: 東京都内」はプレースホルダーに近い不足表示

- 根拠: `src/data/siteData.js` の所在地は「東京都内」。
- 評価: 架空LPなので実住所の真偽は問わないが、表示例としては `東京都〇〇区〇〇...` など、架空であることが分かる具体例の方がよい。
- 影響: 特商法表記のサンプルとしては未完成に見える。

## 改善提案

1. 特商法表記の行を、最低限以下まで増やす。
   - 販売事業者名
   - 代表責任者
   - 所在地
   - 電話番号または問い合わせ先
   - メールアドレス
   - 受付時間
   - 販売価格
   - 商品代金以外の必要料金
   - 支払い方法
   - 支払い時期
   - 商品の引き渡し時期
   - 返品・交換・キャンセル
2. 架空LPであることを維持する場合も、`架空の表示例です` と明記したうえで、住所や連絡先は `〒000-0000 東京都〇〇区...` のようなサンプル値にする。
3. 問い合わせ窓口は、フォームへのリンク、メール、電話番号のいずれかを具体的に表示する。
4. 返品条件は法務ページ、FAQ、カート、購入パネルで同じ条件に統一する。
5. プライバシーポリシーに最終更新日、利用目的、第三者提供、安全管理、開示・訂正・削除、Cookie/アクセス解析、問い合わせ窓口、変更方針を明示する。
6. 法務ページ内アンカーは、SPAルーティングと衝突しない方式にする。例: `#legal-commerce` / `#legal-privacy` へ変更する、またはページ内スクロールをReact側で処理する。
