## 詰まり（1つ）
- AIが出したパーツを“全部正しい前提”で足していくと、**既存のHTML構造（class/入れ子）とCSS前提が食い違って**、見た目が一気に崩れる。特に「セクション追加」「wrapper増減」「class名の改名」が混ざると、どこが原因か追いづらくなった。新しくまるっとサイトのコードを生成すると、クラス構造が変わってしまい、既存のサイトのブラッシュアップには使いにくかった。

## 学び（1行）
- AI提案は「差分を小さく→1回ごとに見た目確認→効いた案だけ残す」が最短で、HTML（構造）とCSS（前提）を同時にいじるとデバッグが指数的に重くなる。Thinkingモードも使い分けが必要。

## 良かったこと（1つ）
- “提案を全部入れる”をやめて、採用基準（壊さない・目的に直結・差分が小さい）を置いたら、復旧〜改善まで一気に前に進められた

## 次回やること
- 取り込んだ改善案を「必須（CV導線）／任意（見た目）／保留（崩れる）」に仕分けして、採用の優先順位を固定する
- HTMLのセクション構造（wrapper/inner/container）をテンプレとして統一し、class命名もルール化して“対応しないCSS”を増やさない
- CSSの追加は末尾に寄せつつ、重複を定期的に掃除（同じプロパティが散らばらないように）して保守性を上げる
- レスポンシブと導線の最終チェック（スマホでのCTA、アンカー、フォーム到達）を1セットの手順にして毎回回す
