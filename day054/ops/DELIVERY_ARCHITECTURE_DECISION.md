# DELIVERY_ARCHITECTURE_DECISION

## 目的
- 公開方式と実装方式の候補、制約、未確定点を整理する。

## 候補案
| 案 | 想定方式 | メリット | リスク | 判断 |
| --- | --- | --- | --- | --- |
| A | 既存 WordPress に固定ページとして実装 | 運用先が一本化される。公開後に文言修正しやすい | テーマ干渉、ビルダー制約、編集自由度の誤認 | 第一候補 |
| B | HTML/CSS で LP を制作し、WordPress には貼り込み or 限定反映 | デザイン自由度が高く、検証しやすい | 反映方法によっては再編集しにくい | 代替候補 |

## 確認済み事項
- CMS: WordPress 希望あり
- テーマ: SWELL
- ビルダー: ブロックエディタ主体。一部 SWELL ブロック / カラムレイアウトあり
- フォーム方式: Contact Form 7 を既存問い合わせページで利用
- 予約導線: 既存の Contact Form 7 から無料相談を受け、日程調整はメールで行う前提
- 計測タグ導入経路: 未確認
- 固定ページ追加: 可能
- 固定ページ一覧: シンプルなページ構成で、今回のLP用固定ページを追加しても管理しづらい状態ではなさそう
- 1カラムページ: 比較的シンプルな構成なら作成できそう
- 編集画面: ページタイトル欄、見出し / 段落 / 画像 / ボタン / カラム / スペーサーなどの一般的なブロックを利用可能想定
- ページ設定: サイドバー表示、ページタイトル表示、コンテンツ幅に関する設定項目が見える想定
- フォーム項目: 現時点では既存項目を活かし、項目自体の大きな見直しは行わない方針
- テーマ運用: 有効テーマは SWELL のみで、極端に独自仕様の強い環境ではなさそう
- HTML / CSS 調整: 大きな改修は想定せず、軽微な CSS 追加は対応可能想定

## 未確定点
- 既存サイト内のどこへ置くか
- 固定ページ編集画面上で、LP 用のレイアウトがどこまで既存機能で収まるか
- HTML / CSS / JS の投入方法
- 公開後にクライアントが触る範囲
- 1カラム化、幅制御、サイドバー非表示、ページタイトル表示調整の可否
- 管理画面から文言差し替えしやすい反映方式にできるか
- テーマやエディタ都合で再現が難しい場合の代替案
- 実際の管理画面で、文章補足と大きく異なる制約が出ないか
