# キックオフ議事録チェックリスト
## 02 Kickoff Meeting Checklist

**使う場面**: 受注後のキックオフ、着手前の初回定例、役割分担と進行ルールを固定するとき

## この場面の目的
- 受注前に決めた範囲を、着手前の実務ルールへ落とす。
- 後から `そんな想定ではなかった` を防ぐ。

## キックオフで固定すること

### 目的と範囲
- [ ] 今回の主目的を確認した
- [ ] 今回の成果物を確認した
- [ ] 今回含まない範囲を確認した
- [ ] 軽微修正の扱いを確認した

### スケジュール
- [ ] 初稿提出日を確認した
- [ ] 確認期限を確認した
- [ ] 公開希望日を確認した
- [ ] 返答が止まったときの扱いを確認した
- [ ] 確認対象URLまたは確認方法を固定した
- [ ] どの段階を `承認` とみなすか確認した
- [ ] 古い版を見ての差し戻しを防ぐルールを確認した

### 体制
- [ ] 決裁者を確認した
- [ ] デザイン確認者を確認した
- [ ] 技術 / WordPress 確認者を確認した
- [ ] 広告や集客担当との連携要否を確認した

### コミュニケーション
- [ ] 連絡手段を確認した
- [ ] 通常の返信目安を確認した
- [ ] 修正依頼の出し方を確認した
- [ ] 緊急時の連絡方法を確認した

### 素材とアクセス
- [ ] 素材提出の締切を確認した
- [ ] 実績掲載可否の確認担当を決めた
- [ ] WordPress / GA4 / Meta / フォームのアクセス取得方法を確認した
- [ ] 受信先メールや通知先の確認担当を決めた

## 議事録に残すべきこと
- [ ] 決まったこと
- [ ] 保留事項
- [ ] 担当者
- [ ] 期限
- [ ] 次回までの宿題

## 完了条件
- [ ] `HANDOFF_LOG.md` に議事録要約を残した
- [ ] 保留事項が誰ボールか明確
