# 計測設計・計測実装チェックリスト
## 13 Measurement Setup Checklist

**使う場面**: GA4やMetaなどの最小計測を設計・実装・確認するとき

## この場面の目的
- 最小計測だけを安全に入れる。
- `測れること` と `測れないこと` を先に分ける。

## 計測前提
- [ ] `06_account_access_and_ownership_checklist.md` が完了している
- [ ] GA4 所有権を確認した
- [ ] Meta 所有権を確認した
- [ ] GA4 へ実ログインできることを確認した
- [ ] Meta または指定確認手段へ実ログインできることを確認した
- [ ] タグ注入経路を確認した
- [ ] フォーム / 予約の完了地点を確認した
- [ ] 主CV を直接計測できるか確認した
- [ ] 直接計測できない場合の代替証跡を決めた

## 最小計測
- [ ] CTA 総数
- [ ] CTA 位置別
- [ ] 主要セクション到達
- [ ] フォーム開始
- [ ] フォーム送信着手
- [ ] フォーム送信完了または予約完了
- [ ] UTM 保持

## 注意
- [ ] native form を壊していない
- [ ] `送信着手` と `送信完了` を混同していない
- [ ] LPイベントだけで最終契約率改善を断定しない
- [ ] 手動運用の部分は証跡が弱いと説明できる

## 発火検証
- [ ] GA4 Realtime または DebugView で主要イベント発火を確認した
- [ ] Meta Test Events または同等手段で主要イベント発火を確認した
- [ ] 同一操作でイベントが重複発火していないことを確認した
- [ ] UTM や主要パラメータが意図どおり保持されるか確認した
- [ ] テスト時の確認手順と結果を記録した

## 代替証跡と限界
- [ ] 予約件数の代替確認元を決めた
- [ ] フォーム通知件数の取得元を決めた
- [ ] 外部流入要因の記録方法を決めた
- [ ] `何が測れて / 何が測れないか` をクライアントへ説明できる
- [ ] レビュー時に使う証跡の保存場所を決めた

## 完了条件
- [ ] `MEASUREMENT_EXECUTION_PLAN.md` を記入した
- [ ] `MEASUREMENT_VALIDATION_LOG.md` で動作確認を残した
