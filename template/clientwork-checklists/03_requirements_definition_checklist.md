# 要件定義・確定条件整理チェックリスト
## 03 Requirements Definition Checklist

**使う場面**: ヒアリング後に、確定条件と保留条件を整理するとき

## この場面の目的
- `確定` `保留` `含まない` を分ける。
- 曖昧な期待を、実務上の条件に落とす。

## 要件整理チェック

### 目的と成果物
- [ ] 主目的を一文で書ける
- [ ] 副目的を列挙できる
- [ ] 公開時点での成功条件を定義した
- [ ] 公開後レビューまで含むか切り分けた

### ターゲットと訴求
- [ ] 最優先ターゲットを1つに絞った
- [ ] 主要な悩みを3つ以内に絞った
- [ ] 何を相談 / 予約 / 問い合わせできるのか言語化した
- [ ] 競合との差を仮でも定義した

### 導線
- [ ] 主導線を確定した
- [ ] 副導線を初回制作に含めるか決めた
- [ ] 予約後 / 問い合わせ後の流れを確認した
- [ ] 予約ツールやフォームの運用者を確認した

### 素材と法務
- [ ] 原稿の有無を確認した
- [ ] 写真素材の有無を確認した
- [ ] 実績 / 事例 / 声の掲載可否を確認した
- [ ] 法務ページの有無を確認した
- [ ] 個人情報取得や同意文言の要否を確認した

## 要件の危険信号
- [ ] `自分でも簡単に直したい` の中身を具体化した
- [ ] `LPっぽくしたい` を具体要件へ言い換えた
- [ ] `数字も見たい` の範囲を具体化した
- [ ] `できれば少し見てほしい` を別フェーズ候補として分離した

## 完了条件
- [ ] `REQUIREMENTS_CONFIRMED.md` に確定 / 保留を記入した
- [ ] 口頭期待をそのまま要件扱いしていない
