# 公開直後の安定化チェックリスト
## 11 Post Release Stabilize Checklist

**使う場面**: 公開直後に、修正優先度を整理して事故を収束させるとき

## この場面の目的
- 公開直後の事故を短期で収束させる。
- ここで分析論点を増やしすぎない。

## 公開直後チェック
- [ ] クライアント確認事項を明確に伝えた
- [ ] Blocker / High / Medium / Low に分類した
- [ ] 修正対象が `公開品質` か `改善論点` かを分けた

## 優先度判定
- [ ] 主要CTA不通は Blocker とした
- [ ] フォーム通知異常は Blocker とした
- [ ] スマホ崩れは High とした
- [ ] 文言や余白の細かい調整は Medium / Low に分けた

## スコープ防衛
- [ ] 公開直後の軽微修正に含む範囲を守った
- [ ] 大幅構成変更をその場で無償対応にしていない
- [ ] 計測拡張や新導線追加は別フェーズ候補として切った

## 完了条件
- [ ] `CLIENT_FEEDBACK_TRACKER.md` と `FIX_PRIORITY_MATRIX.md` が更新されている
