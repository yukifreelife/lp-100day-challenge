# 公開前バックアップ・ロールバック確認チェックリスト
## 10 Backup And Rollback Checklist

**使う場面**: 既存サイトや WordPress に本番反映する前、復旧手順を先に固定するとき

## この場面の目的
- 公開で崩したときに `戻せない` 状態を防ぐ。
- 既存環境への反映を、復旧前提で行う。

## バックアップ確認
- [ ] 反映前の HTML / CSS / JS / 設定の保存場所を決めた
- [ ] 既存固定ページや対象ページのバックアップを取得した
- [ ] 使用中テーマ / ビルダー / プラグインの影響範囲を控えた
- [ ] フォーム設定や通知設定の現状値を控えた
- [ ] GA4 / Meta / GTM の設定値や現状実装を控えた
- [ ] ホスト側または WordPress 側の復元可能なバックアップがあることを確認した

## ロールバック手順
- [ ] どこまで戻せば復旧完了かを決めた
- [ ] 戻し作業を誰が行うか決めた
- [ ] 緊急時の連絡先を決めた
- [ ] ロールバックに必要な権限が揃っていることを確認した
- [ ] クライアントへ `復旧時はどこまで戻すか` を説明できる
- [ ] 少なくとも復元手順の確認または復元可能性の確認をした

## 公開時の判断
- [ ] バックアップ未取得のまま反映しない
- [ ] ロールバック不可の状態で本番変更しない
- [ ] 既存ページ上書き時は復旧手順を先に残した

## 完了条件
- [ ] バックアップ保存場所が記録されている
- [ ] ロールバック手順が手順書または `HANDOFF_LOG.md` に残っている
- [ ] `戻せる見込みがある` を説明できる状態
