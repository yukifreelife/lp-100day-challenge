# クライアント対応 レスポンスパターンガイド

**目的**: クライアントからの質問・依頼に対する回答パターンを体系化し、対応品質の標準化を図る。

**使い方**:
- 各パターンは状況に合わせて調整する
- クライアントの性格・関係性に合わせてトーンを調整する
- 「選択肢を提示する」スタイルを基本とする

## 1. 複数選択肢を提示するパターン

### 基本構造

**「A・Bどちらがお好きですか？」ではなく「A・Bどちらでもいいです」を引き出す**

```
件名: Re: {{相談事項}}について

{{クライアント名}} 様

お世話になっております。

{{議題}}につきまして、
{{選択肢A}}と{{選択肢B}}の2パターンを検討しております。

## 選択肢A: {{タイトル}}

- メリット: {{メリット}}
- デメリット: {{デメリット}}
- 工数: {{工数}}
- 費用: {{費用}}

## 選択肢B: {{タイトル}}

- メリット: {{メリット}}
- デメリット: {{デメリット}}
- 工数: {{工数}}
- 費用: {{費用}}

## ご提案

{{判断基準}}の観点から、
今回は{{選択肢A}}をお勧めしております。

ただ、{{クライアント側の状況}}によっては
{{選択肢B}}の方が運用しやすい場合もございます。

いかがでしょうか。

よろしくお願いいたします。
```

### バリエーション例

#### 実装方式の選択
- テーマ開発 vs 既存テーマカスタマイズ
- プラグイン利用 vs 自作実装

#### スケジュールの選択
- まとめて公開 vs 段階的公開
- 先にA部分 vs 先にB部分

## 2. フィードバック対応パターン

### 2.1 ポジティブなフィードバックへの応答

```
件名: Re: {{件名}}

{{クライアント名}} 様

お世話になっております。

ご確認ありがとうございます。
{{良い評価部分}}について、評価いただき大変嬉しく存じます。

特に{{特定の評価ポイント}}とのご意見は、
私どもも{{制作意図}}として重視しておりましたので、
評価いただけて安心いたしました。

引き続き、残りの{{作業内容}}も進めてまいります。

よろしくお願いいたします。
```

### 2.2 修正フィードバックへの応答

```
件名: Re: {{件名}}

{{クライアント名}} 様

お世話になっております。

ご指摘いただいた{{点数}}点について、
確認いたしました。

## 修正対応内容

1. {{修正項目1}}
   - ご指摘: {{クライアントの指摘内容}}
   - 対応: {{具体的な対応内容}}

2. {{修正項目2}}
   - ご指摘: {{クライアントの指摘内容}}
   - 対応: {{具体的な対応内容}}

## ご相談させていただきたい点

{{相談事項}}につきまして、
{{選択肢A}}/{{選択肢B}}のいずれかで対応可能です。
今回は{{推奨案}}を推奨しておりますが、いかがでしょうか。

{{日付}}頃に修正版をお送りできる予定です。

よろしくお願いいたします。
```

### 2.3 大幅な修正依頼への応答

```
件名: Re: {{件名}}

{{クライアント名}} 様

お世話になっております。

ご確認とごフィードバックありがとうございます。

ご指摘いただいた{{修正内容}}につきまして、
検討いたしました。

## 現状のご確認

当初の{{合意内容}}の範囲では{{現在の対応}}となっておりますが、
ご要望の{{新しい内容}}を実現するには、
{{追加作業}}が必要となります。

## 選択肢

### 選択肢1: 追加対応として実施
- 内容: {{追加作業内容}}
- 工数: {{追加工数}}
- 費用: {{追加費用}}
- 納期: {{新しい納期}}

### 選択肢2: 今回の範囲内で調整
- 内容: {{範囲内での対応内容}}
- 工数: {{既存工数内}}
- 費用: {{追加費用なし}}
- 納期: {{既定納期}}

### 選択肢3: 次回改善案件として検討
- 内容: {{次回の改善内容}}
- 今回: {{今回の対応内容}}

いかがでしょうか。

よろしくお願いいたします。
```

## 3. タイムライン調整パターン

### 3.1 納期延期の依頼

```
件名: スケジュールの調整について

{{クライアント名}} 様

お世話になっております。

{{制作物}}のスケジュールについて、
ご相談させていただきたいことがございます。

## 現状

当初予定しておりました{{日付}}の納期につきまして、
{{延期理由}}により、{{新しい日付}}への延期をお願いしたく存じます。

## 延期の理由

- {{理由1}}: {{詳細}}
- {{理由2}}: {{詳細}}

## 新しいスケジュール

- {{マイルストーン1}}: {{新しい日付1}}
- {{マイルストーン2}}: {{新しい日付2}}
- {{納品}}: {{新しい納期}}

## 今後の対応

遅れが出ないよう、{{対策}}を実施しております。

ご不便をおかけいたしますが、
何卒ご理解いただけますようお願い申し上げます。

よろしくお願いいたします。
```

### 3.2 クライアント側の遅れ対応

```
件名: Re: {{件名}}

{{クライアント名}} 様

お世話になっております。

{{遅れている事項}}の状況について確認いたしました。

## 影響範囲

{{項目}}の遅れにより、
以下のスケジュールに影響が出ております。

- {{影響を受ける項目1}}: {{影響内容}}
- {{影響を受ける項目2}}: {{影響内容}}

## 提案

{{遅れている項目}}が{{タイミング}}までに揃う場合、
{{新しいスケジュール}}での対応が可能です。

もしさらに遅れるようであれば、
{{代替案}}もご検討いただけますと幸いです。

ご確認のほど、よろしくお願いいたします。
```

## 4. 不具合対応パターン

### 4.1 不具合報告受領時

```
件名: Re: {{不具合内容}}について

{{クライアント名}} 様

お世話になっております。

ご報告いただいた不具合について確認いたしました。

## 確認事項

- 不具合内容: {{内容}}
- 発生環境: {{環境}}
- 発生頻度: {{頻度}}

## 原因調査

{{調査内容}}

## 次のステップ

{{対応予定}}までに原因特定と対応方針のご連絡をさせていただきます。

ご不便をおかけいたしますが、今しばらくお待ちください。

よろしくお願いいたします。
```

```
件名: Re: {{不具合内容}}について

{{クライアント名}} 様

お世話になっております。

{{不具合内容}}の原因が特定できましたので、
対応方針をご報告いたします。

## 原因

{{原因の説明}}

## 対応方針

{{選択肢A}}と{{選択肢B}}の2パターンがございます。

### 選択肢A: {{タイトル}}
- 内容: {{対応内容}}
- メリット: {{メリット}}
- デメリット: {{デメリット}}
- 所要時間: {{時間}}

### 選択肢B: {{タイトル}}
- 内容: {{対応内容}}
- メリット: {{メリット}}
- デメリット: {{デメリット}}
- 所要時間: {{時間}}

## ご提案

今回は{{選択肢A}}をお勧めしております。

いかがでしょうか。

よろしくお願いいたします。
```

### 4.3 緊急不具合対応

```
件名: 【重要】{{不具合内容}}の緊急対応について

{{クライアント名}} 様

お世話になっております。

{{不具合内容}}につきまして、緊急対応を実施いたします。

## 現在の状況
{{状況説明}}

## 実施した対応
{{対応内容}}

## 今後の予定
{{今後の対応}}

引き続き、状況をご報告させていただきます。

何卒よろしくお願いいたします。
```

## 6. 決定促進パターン

### 6.1 複数案からの決定促進

```
件名: Re: {{議題}}について

{{クライアント名}} 様

お世話になっております。

{{議題}}につきまして、
これまで{{案数}}パターンをご提示してまいりましたが、
決定の方向性はお決まりでしょうか。

## これまでのご提案

- {{案A}}: {{特徴}}
- {{案B}}: {{特徴}}
- {{案C}}: {{特徴}}

## ご提案

{{判断基準}}の観点から、
今回は{{推奨案}}をお勧めしております。

{{決定に必要な残タスク}}がございましたら、
{{期限}}までにご共有いただけますと幸いです。

よろしくお願いいたします。
```

### 6.2 最終確認依頼

```
件名: {{作業}}の最終確認のお願い

{{クライアント名}} 様

お世話になっております。

{{作業内容}}が完了いたしましたので、
最終確認をお願いできますでしょうか。

## 確認事項

- [ ] {{確認項目1}}
- [ ] {{確認項目2}}
- [ ] {{確認項目3}}

## 次のステップ

ご確認が取れ次第、{{次の作業}}に進めさせていただきます。

{{期限}}までにご確認いただけますと幸いです。

よろしくお願いいたします。
```

## レスポンスパターンの原則

### 1. 選択肢を常に提示する
- 「できません」ではなく「Aならできます、Bならできます」
- クライアントに選択権があることを示す

### 2. 推奨案を明示する
- 選択肢がある場合は推奨案を示す
- 推奨理由も明確にする

### 3. 次のアクションを明確にする
- 「何を」「いつまでに」依頼するか
- 次の確認タイミングを示す

### 4. 期待値を管理する
- できること・できないことを明確に
- 工数・費用・納期への影響を示す

### 5. トーンを維持する
- 親身すぎず、事務的すぎず
- プロフェッショナルな距離感を保つ
